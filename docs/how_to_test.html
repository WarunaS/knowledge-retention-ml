1. Quick start

cd knowledge-retention-ml
uv venv && source .venv/bin/activate
uv pip install -e ".[dev,clean,explore,ml,label,app,dashboard]"

pytest                          # 140 fast tests, ~10 s
python scripts/smoke_test.py    # whole pipeline on tiny real data, ~1.5 min, no API cost
If both finish without errors, the code works on your machine. The rest of this page explains each piece and how to do the real run.

The code does not read a .env file. .env.example lists the variables as a reminder only. Set them in your shell, or from Colab secrets.

Set them locally (macOS / Linux)

export ANTHROPIC_API_KEY="sk-ant-..."          # only for paid steps
export KRS_DATA_ROOT="$HOME/krs/data"          # optional: keep data outside the repo
export KRS_RESULTS_DIR="$HOME/krs/results"
export KRS_MODELS_DIR="$HOME/krs/models"
export OMP_NUM_THREADS=4 TOKENIZERS_PARALLELISM=false

Set them in Colab

The first cell of every notebook already sets the three KRS_* folders to Google Drive. For the API key, add it once under Colab → 🔑 Secrets as ANTHROPIC_API_KEY, then in the notebook:

import os
from google.colab import userdata
os.environ["ANTHROPIC_API_KEY"] = userdata.get("ANTHROPIC_API_KEY")
Never paste a key into a notebook cell or a config file, and never commit .env (it is gitignored).

5. Level 1 - automated tests free local

pytest                    # fast tests (default): 140, ~10 s, no network
pytest -m slow            # 4 tests: real DeBERTa/SetFit code with tiny models, BERTopic (~20 s)
pytest -m network         # 3 tests: stream real rows from Hugging Face (~20 s, needs internet)
pytest -m "slow or network" -q
pytest tests/test_app.py -q          # one file
pytest -k "privacy or faithfulness"  # by name
ruff check src tests scripts         # lint
No test calls the Claude API: labelling, the teacher, extraction and answers use a fake client. No test touches real own logs.

6. Level 2 - smoke test (whole pipeline) free local

python scripts/smoke_test.py            # ~1.5 min, writes ./smoke/ (gitignored)
python scripts/smoke_test.py --topics   # also BERTopic (+20 s)
python scripts/smoke_test.py --out /tmp/krs-smoke

Runs on tiny real data: collect (WildChat 300, SWE-agent 30, OpenHands 30) → clean → explore → placeholder labels → split → features → B0, B1, B2 → evaluate → register → inference → cards (local backend) → store → ask and handover → retrieval evaluation. Expected ending:

=== 14 Inference (CPU)
    ok in 5.0s | scored: 620 | seconds_per_1k: 7.47
...
SMOKE TEST PASSED. Outputs under .../smoke
Every score it prints is meaningless. The labels are random placeholders so the chain runs without paying for labels or waiting for human raters. For the same reason many cards are rejected with "only a decision was predicted but no decision is stated": the toy model predicts "decision" at random and the faithfulness rule refuses to invent a decision that is not in the text. With real labels this does not happen.

Not covered by the smoke test (they need a GPU, money or consent): M1, A1, A2, M2, teacher T, X1, and the Claude backends.

8. Running on Colab

  1. Open a notebook from GitHub: File → Open notebook → GitHub → WarunaS/knowledge-retention-ml.
  2. For stages 4, 5 and 8: Runtime → Change runtime type → GPU.
  3. Run the first cell: it mounts Drive, clones the repo (git pull on later runs), installs it and sets KRS_DATA_ROOT, KRS_RESULTS_DIR, KRS_MODELS_DIR to MyDrive/krs/.
  4. For paid steps, load the API key from Colab secrets (section 3).
  5. Outputs stay on Drive, so a later notebook (or your laptop with the same folders) picks them up.
If the repo is private, Colab needs a GitHub token to clone; making it public is simplest. Own logs never go to Colab.

10. How to see the results

a) In the notebooks

Notebooks 04, 06, 09, 12, 14, 16 and 17 end with tables and plots for their stage. Notebook 09 shows the results table, hypotheses, per-label scores and confusion matrices.

b) The files for the report

  • results/eval/results_table.md - paste into the report (macro-F1 with 95% CIs per run)
  • results/eval/comparisons.json - H1, H2, H3 verdicts with CIs and p-values
  • models/<version>/model_card.md - the model card
  • results/X1/report.json - transfer drop (RQ3)
  • results/app_eval/retrieval.json and the successor analysis (RQ4)
  • results/eda/*.png, results/eval/*.png - figures

c) Dashboard (one screen)

uv pip install -e ".[dashboard]"
streamlit run src/krs/app/dashboard.py                 # http://localhost:8501

# to look at the smoke-test outputs instead of your real data:
KRS_DATA_ROOT=smoke/data KRS_RESULTS_DIR=smoke/results KRS_MODELS_DIR=smoke/models \
  streamlit run src/krs/app/dashboard.py

Tabs: Ask (local answers by default; Claude only if chosen and a key is set) · Handover pack (download) · Knowledge map (coverage, areas depending on one person - never named, stale areas) · Model results.

d) REST API

uvicorn krs.app.agent:app        # interactive docs: http://localhost:8000/docs

curl localhost:8000/health
curl -X POST localhost:8000/ask -H 'content-type: application/json' \
     -d '{"question": "Why did we choose a queue for order emails?", "filters": {"project_id": "orders"}}'
curl -X POST localhost:8000/search -H 'content-type: application/json' -d '{"query": "deploy steps", "k": 5}'
curl "localhost:8000/handover?project_id=orders"
curl localhost:8000/cards/<card_id>

e) Inside Claude Code (MCP)

claude mcp add krs -e KRS_DATA_ROOT="$PWD/data" -- "$PWD/.venv/bin/python" -m krs.app.mcp_server

Then ask in Claude Code: "Why did the team pick Redis for sessions?". Tools: ask_predecessor, search_knowledge, handover_pack.

f) All experiments at a glance

python -c "from krs import tracking; print(tracking.index_runs().to_string())"

11. Cost and privacy checks

CheckHow
Before weak labellingRun the estimate cell in notebook 05 (about $35-$105 for 10,000 segments with Claude Opus 5.5 in batch mode). Changing model in configs/label.yaml is the main cost lever.
Before the teacher runrun_experiment("T") returns an estimate only (about $4 for 400 gold segments); nothing is sent until confirm=True.
Own logsCollected and cleaned locally, redacted before anything else; never on Colab; card extraction and answers for them always use the local backend (enforced in code and tested).
X1Runs once; the lock file records any forced re-run and its reason; the report holds ids and numbers only.
PeoplePseudonyms only; the knowledge map never names contributors; nothing ranks or scores individuals; store.delete_person(id) erases a person's cards everywhere.

12. Troubleshooting

SymptomCause and fix
FileNotFoundError: ... run Stage X firstA stage's input is missing. Run the stages in order, with the same KRS_* folders.
Hugging Face warning about unauthenticated requestsHarmless. Set HF_TOKEN for higher rate limits.
DeBERTa tokenizer error mentioning tiktoken or protobufInstall the ml extra (it includes sentencepiece and protobuf).
Answer says "No Anthropic API key is set; answered locally"Intended fallback: the REST API, MCP and dashboard never crash without a key. Set ANTHROPIC_API_KEY (section 3) for written Claude answers on public-source cards.
RuntimeError: extraction backend is 'claude' but no ANTHROPIC_API_KEY is setSet the key, or set extraction.backend: local in configs/app.yaml (free, extractive cards).
authentication / 401 from Claude in paid stepsThe key is wrong or not set in this process (section 3).
TransferLockError: X1 already ranIntended. Re-run only with transfer.run(force=True, reason="...").
RegistrationError: not evaluated on the gold setRun notebook 09 for that run first.
Many cards rejected in the smoke testExpected with placeholder labels (section 6).
Laptop slow during embeddings or slow testsexport OMP_NUM_THREADS=4 TOKENIZERS_PARALLELISM=false; run the full sizes on Colab.
Colab disconnectedOutputs are on Drive; re-run the notebook. Stage 4b batches, extraction and inference resume where they stopped.

13. A-to-Z checklist

  1. Install (section 1) and set the environment variables you need (section 3).
  2. pytest, pytest -m slow, pytest -m network all pass.
  3. python scripts/smoke_test.py ends with "SMOKE TEST PASSED"; open the dashboard on smoke/ to see every tab working.
  4. Approvals: supervisor sign-off, ethics approval, written consent from teammates.
  5. Colab: Stage 2 dry run (limit: 200), then full collection.
  6. Stage 3, fill the precision sheet; Stage 4, read the taxonomy coverage.
  7. Stage 4b: gold sheets to both raters; weak labels after checking the cost estimate; noise check; κ ≥ 0.6 or revise the codebook once.
  8. Stage 6, then 5; check the split report and token lengths.
  9. Stage 7 baselines; Stage 8 M1, A1, A2, M2 on GPU; teacher T after its estimate.
  10. Stage 9 evaluate; Stage 12 register; read the model card.
  11. Stage 14 inference; check the knowledge-bearing share.
  12. X1 locally, once, on consented and redacted own logs.
  13. App: extract cards, build the store, try ask, handover, REST, MCP, dashboard.
  14. App evaluation: card check, own-words questions, successor sessions, blind rating.
  15. Write-up from results_table.md, comparisons.json, the model card, X1 and app evaluation outputs.
